INTRODUCTION                                                    *ci* *ci.nvim*

GitHub Actions status and logs for whatever you are working on. One command,
|:CI|, and no configuration.

==============================================================================
REQUIREMENTS                                                 *ci-requirements*

- Neovim 0.11+
- The GitHub CLI, `gh`, authenticated (`gh auth login`)
- `git`

==============================================================================
INSTALL                                                           *ci-install*

With |vim.pack| (Neovim 0.12+): >lua
    vim.pack.add({
      'https://forge.barrettruth.com/barrettruth/ci.nvim',
    })
< Or via luarocks: >
    luarocks install ci.nvim
<
==============================================================================
COMMAND                                                          *ci-commands*

                                                                         *:CI*
:CI                     Show checks for the active pull request on the current
                        branch. Falls back to the branch head if no pull
                        request is open.

:CI {rev}               Show checks for a git revision. {rev} is resolved by
                        GitHub, not locally, so `:CI master` is the real tip
                        of master rather than a (possibly) stale local ref.
                        Accepts anything git-rev-parse accepts: branches,
                        tags, SHAs, `master~3`. Non-commits and ranges are
                        rejected.

                        Note that `:CI HEAD` is therefore the remote default
                        branch. Use |:CI| with no args for your working
                        state.

:CI {url}               Show a github.com URL. Recognised:
                          .../actions/runs/{run}/job/{job}    a job log
                          .../actions/runs/{run}              a run
                          .../actions/runs/{run}/attempts/{n} one attempt
                          .../runs/{check_run_id}             a job log
                          .../actions/workflows/{file}        its latest run
                          .../pull/{n}[/checks]               a pull request
                          .../commit/{sha}[/checks]           a commit
                          .../actions                         the repository
                        A `#step:{n}:{line}` fragment is accepted and ignored.

:CI ci://...            Reopen a ci.nvim buffer by name. See |ci-buffers|.

:CI .                   Use the |<cWORD>| under the cursor as the argument.

Window modifiers split rather than replace: `:vertical CI`, `:tab CI`,
`:botright CI`. `:pedit ci://...` works too.

Repository resolution is delegated entirely to `gh`, which means fork pull
requests resolve to the base repository (where checks usually live). If `gh`
picks the wrong repository, fix it with `gh repo set-default`.

==============================================================================
BUFFERS                                                           *ci-buffers*

Buffers are named, so `:edit` reloads them and `:CI` on the name reopens them:
>
    ci://{owner}/{repo}/job/{job_id}
    ci://{owner}/{repo}/run/{run_id}[/{attempt}]
    ci://{owner}/{repo}/pr/{number}
    ci://{owner}/{repo}/checks/{oid}
<
There is no polling. Press `:e` or `R` to refresh; the cursor and scroll
position are kept. Re-running |:CI| for a buffer that is already open just
moves to its window without refetching.

A job buffer folds two levels by default: step, then `##[group]`. The first
failing step is opened and the cursor placed on it. Interact with the folds as
you would regularly; `zM`/`zR` collapses/expands the step list. For example,
to disable all folds always: >lua
    vim.api.nvim_create_autocmd('BufWinEnter', {
      pattern = 'ci://*',
      callback = function()
        vim.wo[0][0].foldenable = false
      end,
    })
< Fold options are set on |BufWinEnter|, so a |FileType| autocmd is too early.

Actions logs are (mostly) concealed and transformed rather than deleted. For
example, every line keeps its timestamp and internal `##[...]` marker which
are then hidden with |conceal|. Step headers are added for clarity, and
`##[endgroup]` is dropped, having become the end of a fold.

Show log timestamps (hidden by default) with `gS` or via setting
`conceallevel` natively. The former is formatted for reading, the latter
uncovers the concealed prefixes (ISO timestamps, `##[...]` markers). Neither
is the raw log; for that, see |:terminal| below.

Escape sequences are the only other bytes removed: SGR ones become highlights,
the rest have nothing to say in a text buffer. Use the |:terminal| to view the
log exactly as GitHub stores it: >
    :term gh api repos/{owner}/{repo}/actions/jobs/{job_id}/logs
<

MAPPINGS                                                         *ci-mappings*

Buffer-local defaults, only set if you have not mapped the |<Plug>| target:

    <CR>    <Plug>(ci-open)        In a checks list, open the check under
                                   the cursor. Checks that are not Actions
                                   jobs open in a browser.
    -       <Plug>(ci-up)          Go back to the list you came from.
    R       <Plug>(ci-refresh)     Reload, same as `:e`.
    ]]      <Plug>(ci-next-step)   In a job log, go to the next step.
    [[      <Plug>(ci-prev-step)   In a job log, go to the previous step.
    gS      <Plug>(ci-timestamps)  In a job log, toggle the timestamps.
    gX      <Plug>(ci-web)         Open the current buffer on github.com.
    g?      <Plug>(ci-help)        This section.

To rebind, map the |<Plug>| target and the default is skipped: >lua
    vim.keymap.set('n', '<C-]>', '<Plug>(ci-open)')
<
==============================================================================
HIGHLIGHTS                                                     *ci-highlights*

All groups are links and can be overridden.

    CiPass       ->  DiagnosticOk      ✓  success
    CiFail       ->  DiagnosticError   ✗  failure, timed out, startup failure
    CiRunning    ->  DiagnosticWarn    ●  in progress
    CiPending    ->  Comment           ○  queued, waiting, requested
    CiSkipped    ->  Comment           ⊘  skipped, neutral, stale, cancelled
    CiAttention  ->  DiagnosticWarn    !  action required
    CiGroup      ->  Title                a `##[group]` heading
    CiCommand    ->  Directory            a `[command]` line
    CiUrl        ->  Underlined           a link in the log
    CiMuted      ->  Comment              secondary columns

Log colours are derived from the ANSI escapes in the log itself and follow
your terminal palette (`g:terminal_color_0` through `g:terminal_color_15`).
