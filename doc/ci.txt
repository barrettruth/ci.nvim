INTRODUCTION                                                    *ci* *ci.nvim*

ci.nvim shows GitHub Actions status and logs for whatever you are working on,
in a normal Neovim buffer with real highlighting and folds.

It has one command, |:CI|, and no required configuration.

Logs are fetched from the raw Actions API, not `gh run view --log`, which
replaces every escape byte with the literal characters `^[`. ANSI SGR
sequences are parsed and applied as |extmarks|, so the buffer stays a text
buffer: |search()|, folds, and yanking all behave normally.

==============================================================================
REQUIREMENTS                                                 *ci-requirements*

- Neovim 0.11 or newer
- The GitHub CLI, `gh`, authenticated (`gh auth login`)
- `git`

==============================================================================
INSTALL                                                           *ci-install*

With |vim.pack| (Neovim 0.12+): >lua
    vim.pack.add({
      'https://forge.barrettruth.com/barrettruth/ci.nvim',
    })
< Or via luarocks: >
    luarocks install ci.nvim
<

COMMAND                                                          *ci-commands*

                                                                         *:CI*
:CI                     Show checks for the active pull request on the current
                        branch. Falls back to the branch head if no pull
                        request is open.

:CI {rev}               Show checks for a git revision. {rev} is resolved by
                        GitHub, not locally, so `:CI master` is the real tip of
                        master rather than a possibly stale local ref. Accepts
                        anything git-rev-parse accepts: branches, tags, SHAs,
                        `master~3`. Non-commits and ranges are rejected.

                        Note that `:CI HEAD` is therefore the remote default
                        branch. Use bare |:CI| for your working state.

:CI {url}               Show a github.com URL. Recognised:
                          .../actions/runs/{run}/job/{job}    a job log
                          .../actions/runs/{run}              a run
                          .../actions/runs/{run}/attempts/{n} one attempt
                          .../runs/{check_run_id}             a job log
                          .../actions/workflows/{file}        its latest run
                          .../pull/{n}[/checks]               a pull request
                          .../commit/{sha}[/checks]           a commit
                          .../actions                         the repository
                        A `#step:{n}:{line}` fragment is accepted and ignored.

:CI ci://...            Reopen a ci.nvim buffer by name. See |ci-buffers|.

:CI .                   Use the |<cWORD>| under the cursor as the argument.

Window modifiers apply: `:vertical CI`, `:tab CI`.

Repository resolution is delegated entirely to `gh`, which means fork pull
requests resolve to the base repository, where their checks actually live. If
`gh` picks the wrong repository, fix it with `gh repo set-default`. ci.nvim
has no option for this.

==============================================================================
BUFFERS                                                           *ci-buffers*

Buffers are named, so `:edit` reloads them and `:CI` on the name reopens them:
>
    ci://{owner}/{repo}/job/{job_id}
    ci://{owner}/{repo}/run/{run_id}[/{attempt}]
    ci://{owner}/{repo}/pr/{number}
    ci://{owner}/{repo}/checks/{oid}
<
There is no polling. Press `:e` to refresh.

A job buffer folds two levels: step, then `##[group]`. `zM` collapses to the
step list, with each step's conclusion. The first failing step is opened and
the cursor placed on it.

==============================================================================
MAPPINGS                                                         *ci-mappings*

Buffer-local defaults, only set if you have not mapped the |<Plug>| target:

    <CR>    <Plug>(ci-open)    Open the check under the cursor. Checks that are
                               not GitHub Actions jobs open in a browser.
    -       <Plug>(ci-up)      From a job log, go to its run.
    gX      <Plug>(ci-web)     Open the current buffer on github.com.
    g?      <Plug>(ci-help)    This section.

To rebind, map the |<Plug>| target and the default is skipped: >lua
    vim.keymap.set('n', '<C-]>', '<Plug>(ci-open)')
<
==============================================================================
CONFIGURATION                                                      *ci-config*

There is no `setup()` function. The only option is |vim.g.ci|: >lua
    vim.g.ci = { gh = { 'gh' } }
<
                                                                    *vim.g.ci*
    gh ~
        string|string[], default `{ 'gh' }`

        The GitHub CLI command. Useful for a wrapper script or an absolute
        path.

==============================================================================
HIGHLIGHTS                                                     *ci-highlights*

All groups are links and can be overridden.

    CiPass       ->  DiagnosticOk      ✓  success
    CiFail       ->  DiagnosticError   ✗  failure, timed out, startup failure
    CiRunning    ->  DiagnosticWarn    ●  in progress
    CiPending    ->  Comment           ○  queued, waiting, requested
    CiSkipped    ->  Comment           ⊘  skipped, neutral, stale, cancelled
    CiAttention  ->  DiagnosticWarn    !  action required
    CiGroup      ->  Title                a `##[group]` heading
    CiMuted      ->  Comment              secondary columns

Log colours come from the ANSI escapes in the log itself. The sixteen basic
colours are emitted as indexed, so they follow your terminal palette, or
`g:terminal_color_0` through `g:terminal_color_15` if you have set them.

LUA API                                                               *ci-api*

                                                                    *ci.run()*
ci.run({opts})          Backs |:CI|. {opts} may have `args` and `mods`.

                                                                 *ci.checks()*
ci.checks({cb})         Calls {cb} with a list of checks for the current
                        branch, and the resolved repository. Each check has
                        `name`, `status`, `conclusion`, `url`, `job_id`,
                        `run_id`, and `workflow`.

                        ci.nvim ships no picker integration. Build one: >lua
    vim.keymap.set('n', '<leader>ci', function()
      require('ci').checks(function(checks, repo)
        vim.ui.select(checks, {
          prompt = 'CI',
          format_item = function(c) return c.name end,
        }, function(c)
          if c and c.job_id then
            vim.cmd.edit(('ci://%s/job/%d'):format(repo, c.job_id))
          end
        end)
      end)
    end)
<
                                                                    *ci.url()*
ci.url({buf})           The github.com URL for a ci.nvim buffer, or nil.

HEALTH                                                             *ci-health*
